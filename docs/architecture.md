# Architecture and guarantees

`cmd/apron-home` owns a restricted command surface and loopback listener. It converts fixed security settings through the added `aproncmd.ServerConfig` accessor, then opens the real `apron.Server`. The `closed` extension uses supported Registrar allowlisting, bots, HTTP routes, room operations and lifecycle work. Its local operator API is a private Unix socket, never an HTTP route on the chat listener. OS-user access to the private state directory is operator authority.

The isolated [patch](../patches/README.md) adds invitation-bound preauth registration while retaining upstream go-webauthn verification, resident keys and required user verification. No guest or provisional persisted user is created. Begin saves only connection-local ceremony state. Finish rechecks challenge, origin, RP, identity and invitation under the server lock. Verification failures/abandonment leave the invitation usable until expiry.

Invitation verifiers, explicit owner flags, immutable human account admission and machine credential verifiers are serialized as one extension value in the **same** SQLite store as upstream account/credential records. A new account, used ID, monotonic counters, allowlist and consumed invitation commit in one batch/transaction. The server serializes persistence synchronously and uses WAL + synchronous FULL. Session creation is a later durable transaction: a crash between those commits leaves an authorized passkey account able to log in, not an unauthorized account or reusable invitation.

A failed Apply does not attempt an unreliable memory rollback. It stops further writes, closes WS connections and returns 503 on new HTTP requests. That process requires restart. Restart restores only committed state. SQLite transaction failure and process restart are exercised; real hardware power loss at every filesystem boundary is not. The patch needs independent review before deployment.

Human tokens are hashed, origin-bound, revocable and expire absolutely 30 days after issuance; reconnect does not renew that limit. This is a passkey ceremony at enrollment/login plus bearer resumption, not a ceremony on every reconnect. Existing authenticated sockets are disconnected on revocation; the upstream active-socket lifetime is not a fresh passkey requirement. Device token creation is disabled because upstream device tokens do not expire.

The operator injects a separately generated bot credential in a private runtime file. Only its verifier persists. It authenticates native token connections as the extension-owned `hermes` account with only `bot`, and never yields a human resume token. Bindings expire after seven days; restarting with the same credential does not refresh expiry or undo revocation. Rotate the runtime file intentionally. Bots cannot add human passkeys. Multiple send-only connections coexist with one consumer.

`hermes_apron` extends the pinned real BasePlatformAdapter and registers via PluginContext. Admission by the server and tool authority are independent: the adapter always requires immutable actor IDs, configured joined rooms, and structured bot mentions unless the operator explicitly marks a room as a DM room. `trusted_inbound` is false; gateway authorization remains in place. A thread's native room ID is its Hermes chat ID, preserving conversation and reply isolation.

RPC has independent correlated futures, bounded pending calls, incoming frames/queues and deadlines. Late replies to cancelled requests are ignored. Native writes validate the configured origin and exact write capability path, forbid redirects, use verified TLS, have byte/time limits and never put capability URLs into HTTP-client logs. Arbitrary inbound media URLs are not fetched. Local artifact export accepts private regular files directly in one configured directory using no-follow directory-relative opens.

Recovery subscribes before taking a history high-water boundary. It pages forward to that boundary, processes creation records only, then drains buffered live events; durable IDs/checkpoints suppress duplicates. First installation starts at the current boundary instead of running old chat as commands. Gaps/oversized recovery fail closed. There is a 100,000-ID inbox cap and 100-page recovery bound; an operator must reconcile when those limits are reached.

Dispatch is reserved durably **before** handing a turn to Hermes. A crash after reservation can lose that turn. A crash during tool execution leaves its effects uncertain, and the adapter does not automatically rerun it. There is no transactional outbox spanning tools, models and Apron. A timed-out send may have committed; send-only delivery reports uncertainty as an error. These are at-most-once adapter dispatch choices, not exactly-once execution or guaranteed final-response delivery.

Hermes's public `expect_edits` / `edit_message(finalize=...)` contract drives native append PUTs. Revisions reset only the appended segment; completion retains the same message ID. Missing append falls back to supported edits, or completed text when a core-only peer cannot preview. Writer failure attempts a final save of the same message rather than knowingly posting a second final message. An unknown transport outcome still requires reconciliation.

Push is off. The terminal helper accepts only opt-in, individually approved, bounded **reviewed summaries**. It is not a raw terminal/tool lifecycle integration. Redacting known runtime literals is defense in depth, not permission to stream arbitrary commands, transcripts or environments.
