# Python-native validation contract

Status: scenarios specified, NOT RUN for the new server. The Go implementation's green suites and focused reviews are reference evidence only. Link each scenario to requirement IDs, actual test commands, version/commit, result and limitations in `VALIDATION-RESULTS.md`. Use runtime-generated disposable state and identities. Never run against production Hermes or real authenticators.

## Architecture and no-Go proof

N01 (P2–P6,E1–E3): Import server library, plugin discovery and passive config/status probe in an isolated profile. Assert no listener/task/DB mutation/account creation/model/tool invocation. Instantiate two configured hosts on ephemeral loopback ports with separate state, RP/origin, bot/actor scope and operator controls; prove no cross-profile events, credentials or lifecycle ownership.
N02 (P3,P5): Start real pinned Hermes adapter lifecycle with embedded Python runtime, connect browser/WS peer, receive authorized turn, stream a deterministic fake-model response through the actual Hermes handler/interface, then cancel/disconnect/reconnect. No task/socket/DB worker/lease leak, dangling writers or interruption of unrelated tasks. Failed bind, failed DB open and cancellation at each startup stage unwind cleanly. The controlled fake replaces only the model, not server/adapter/authorization.
N03 (P2,P4): Exercise equivalent allowed and denied commands through network and optional in-process client. Results, scope/visibility, errors, log ordering, dedup and durable commits are equivalent. In-process caller cannot invent another user, role, room scope or approval authority. If no direct client exists, test authenticated loopback transport and explain why it was chosen.
N04 (E1,E3): Build/install/run server and embedded plugin plus default checks in an environment with no Go compiler/runtime/cgo and no Go-server downloads/processes. Run standalone CLI using same library; compare behavior with hosted mode. Old Go reference run remains optional, separate and explicitly labeled. Detect old DB schema and refuse to mutate it; demonstrate clean-state startup and documented rollback to reference.

## Closed enrollment/passkey lifecycle

N05 (S1–S3): Fresh persistent Python server denies guests/open registration/email/external auth/unknown token; exposes only minimum preauth metadata. Local operator issues exactly one account invite with explicit owner flag. No first visitor/default admin. Expired/revoked/replayed/malformed invite never creates an account or exposes a verifier/token in logs.
N06 (S3,S4): Real browser virtual authenticator performs UV passkey enrollment through locally served UI; standard Apron client logs in and chats. Software verifier tests independently cover valid assertion, wrong origin/RP/challenge/action/signature, absent UV, duplicate credential, credential clone/counter policy, expired/reused challenge and concurrent ceremonies. No mocked WebAuthn verifier counts as real verification.
N07 (S4): Simultaneous verified completions for one invite yield exactly one account/credential/admission/owner grant and one consumed invite. Verify database contents in one transaction, failure injection before/within/after each durable boundary, rollback visibility, server/process restart, and commit-success/reply-loss behavior. No event/auth success before durability. Failed/abandoned verification keeps invite usable until expiry. Inject account/invite revocation between verification and commit.
N08 (S6,S7): Add backup passkey after recent reauth, list safe metadata only, selectively revoke one credential without deleting account/messages, and prove revoked credential cannot log in after restart. A stolen/old session cannot add/remove credentials or issue privileged invites. Test last-credential removal policy and explicit whole-account recovery/revocation without backdoor. Revocation invalidates affected sessions per documented policy and disconnects active authorized channels.

## Human/machine authority and native path parity

N09 (S5,F4): Chat-admitted human without Hermes allowlist entry cannot invoke model/tools/approval. Missing actor, display-name spoof, malformed structured mention, bot self-echo and another bot cannot invoke. Two rooms and two child threads have independent sessions, permissions and reply destinations. Room membership grant alone does not widen machine scope.
N10 (S5): Exact machine scope denies aggregate/direct list/history/private/thread metadata/join/create/update/message/edit/move/reply/reaction/typing/upload/stream commands outside scope. Include omitted/default room, parent-filtered listing, known outside message/embed IDs and scope ancestor cases. Allowed private/thread scope works after restart without rebind; scope narrowing persists and revokes active/in-flight operations. Human behavior is tested separately.
N11 (S5,S6): Authenticate machine before short genuine deadline; after expiry all active sockets close and queued/delayed/pipelined commit is denied. Repeat revoke/rotation/restart/scope change/membership leave. Timer generation, replacement, cleanup and restored original deadlines are correct. Separate send-only client remains possible; duplicate consumers across processes/profiles/independent inboxes are refused. Token-file rotation before reconnect never authenticates with an unmatched credential lease.
N12 (S6,S11,F3): BOTH append and terminal writers, over BOTH HTTP and native paths: start authorized, buffer content, then lose authority by revoke, expiry, scope narrowing or membership leave. Every future write/start/close/internal finish/duration-timer finish is denied; forbidden bytes or buffered final snapshot never publish. Invalidate pending writable capabilities. Repeat Close before first Write and cancellation/races. Humans/unrestricted actors keep intended semantics. Test upload body received before authorization loss and commit after loss.
N13 (S6,S9,F3): History/media/read/stream requests cannot reveal private data before authentication or after revocation unless a precisely documented bearer share capability intentionally permits it. Test copied URLs, second account, scope narrowing, credentials in URLs, redirect/SSRF/private-address escape, traversal/symlink/device/FIFO export, MIME/size mismatch, storage exhaustion and interrupted upload. Prove no arbitrary server-local file reads.
N14 (S8,F4): Authorized human resolves the exact pending approval/clarification through actual supported Hermes hooks. Wrong actor/thread/session/request/generation, expired/replayed/ambiguous input and forged reaction are denied; two concurrent requests cannot cross-settle. If no supported affirmative hook exists, prove fail-closed cleanup, mark positive path BLOCKED and do not claim full acceptance.

## Protocol interoperability and hostile peers

N15 (P1,F1): Validate core server/client wire behavior using pinned official schema/wire fixtures plus real Apron clients, not just client/server code sharing one mistaken assumption. Greeting, auth shape, request IDs, order of effect notifications/results, unknown methods/fields, errors, heartbeat and request retry/dedup conform. No accepted forged sender/role/log ID. Pin and record the fixture cases actually covered.
N16 (F2,F6): Pinned unmodified-or-minimally-localized Apron web client performs real rooms/private threads/history/replies/mentions/edit/tombstone/reactions/activity/presence operations against Python server. Browser network assertion: all runtime assets, fonts, WS, files, enrollment and terminal/share links remain local; push disabled. Do not infer phone playback/push from DOM tests. Capture only disposable synthetic UI evidence, no secrets.
N17 (F2,F4): Recover high-water history while live messages race; disconnect mid-turn; replay old creation/edit/reaction/delete records; recreate adapter/process with durable checkpoint. No duplicate completed tool turn or checkpoint poisoning. Test gaps/retention/page/ID exhaustion and unknown send outcome. Document at-most-once loss/crash windows and lack of exactly-once tool effects; never rerun uncertain side effects silently.
N18 (S10): Synthetic WS/HTTP adversaries supply missing/wrong shapes, booleans as numbers, giant integers/nonfinite JSON, oversized frames, deeply nested objects, invalid UTF-8/unpaired surrogate escapes in keys/IDs/names/roles/title/text/receipt URLs, unknown enums and malformed capability responses. Both Python server and adapter reject with bounded fixed errors and no escaped worker exception, retry storm, checkpoint mutation, secret echo or leaked reservations. Valid non-ASCII/astral text is preserved.
N19 (F3,F4): Real append response grows/finalizes in same message, revision/reset/stop/cancel/error behaves correctly, no duplicate final message. Core-only peer fallback completes text without advertising false capabilities. Upload file/image/audio/video readback uses authorized transport. Inline playback/inbound ingestion only marked passed if actually exercised. Reviewed terminal summaries require opt-in/authority and remain bounded/scrubbed; no arbitrary command/env/transcript publication.
N20 (F5): Separate-process scheduled home-room and explicit-thread delivery to embedded Python host; read receipt back while live consumer remains healthy. Auth/room/offline/unknown-outcome errors are surfaced. Scheduled sender does not create another consumer, extend token lifetime or bypass public protocol authorization.

## Durability, resource limits and operations

N21 (P5,S4,S10): Slow serialized DB work and fsync do not block unrelated gateway heartbeats/cancel handling; bounded workers/queues reject overload. Process termination/restart around commit/notification/inbox boundaries preserves atomicity. Corrupt/unavailable policy state fails closed. No multiple concurrent writers evade transactions; backup/restore preserves accounts/revocations/history/IDs/uploads and invite consumption. Document hardware power-loss limits.
N22 (S9,S10): Enforce configured frame/request/connection/auth-rate/history/stream/upload and total-storage/retention quotas; test disk-full, permissions, missing paths, overlong Unix socket path and shutdown under load. Assert fixed nonsecret diagnostics, no busy loops/unbounded growth and no accidental eviction that resurrects revoked credentials. Small deterministic limits make these automated tests, not a claim from default configuration.
N23 (S9,E2,E3): Audit tracked source, all experimental added commits, package artifacts and captured runtime/build logs using canaries. No real credentials/private data read or embedded. Lock/dependency/license checks pass; runtime files/dirs have safe modes. Installation and build use no global/HM/root changes. CI starts from clean checkout, fetches history needed for audit, runs actual Python-hosted suites and distinguishes skipped reference tests from passed tests.
N24 (S1,E4): Operator-only NOT RUN gates: real LAN/non-LAN IPv4+IPv6 isolation, trusted HTTPS and stable RP on actual phones, credential backup/recovery drill, backup restoration and broader security review. Test config syntax/virtual authenticators are not proof. This implementation must NOT perform these deployments implicitly.

## Milestones and acceptance evidence

1. **M0 architecture/reproducibility:** ADR records hosting API, WS/in-process decision, WebAuthn dependency, store transactions, secrets and compatibility; runnable Python package with no-Go proof (N01–N04).
2. **M1 safety vertical slice:** real enrollment/login/chat, atomic invitation and closed human/machine policy with revocation/lifecycle tests (N05–N13). No unsafe temporary guest bootstrap.
3. **M2 native Hermes experience:** actual hosted adapter + pinned frontend, rooms/history/stream/artifacts, safe consent or explicit supported-hook blocker, scheduled delivery and hostile-peer handling (N14–N20).
4. **M3 correction/publication:** durability/resource/secret/license checks, parent execution and independent review (N21–N23); exact feature matrix and known blockers. Implementation agent commits locally only. Parent publishes only reviewed experiment source.
5. **M4 deployment decision:** N24 and all required missing security properties resolved before any live replacement. No automatic rollout, migration, release or Telegram switch.
